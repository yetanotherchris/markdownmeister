# Implementation Plan: Product Icon

**Branch**: `phase-39-product-icon` | **Date**: 2026-08-23 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/039-product-icon/spec.md`

## Summary

Every installation currently shows Electron's default framework icon on every surface. The master artwork and all derived platform assets are already committed (vector master + PNG master + ICO/ICNS/PNG ladder, generated by a zero-dependency PowerShell script); this phase wires them into every packaging channel and the running window: electron-builder keys for Windows/macOS/Linux, the BrowserWindow icon option for win32/Linux, verification that the Linux desktop-entry mechanism finds its icon inside the real electron-builder AppImage layout, binary-format unit tests over the committed assets, provenance documentation, and an optional e2e window-icon assertion.

## Technical Context

**Language/Version**: TypeScript 5.8 strict; YAML config; PowerShell 7 (existing generator script, untouched)

**Primary Dependencies**: None new — electron-builder (already present) consumes the committed assets; tests parse binaries with Node `Buffer` only

**Storage**: Repository-tracked assets (`assets/icon/`, `resources/`) + one extraResources mapping so the runtime window icon exists inside packaged apps

**Testing**: Vitest unit tests (binary structure parsing; AppImage-layout desktop-entry install path); manual visual checklist per [quickstart.md](quickstart.md). The planned e2e window-icon assertion was dropped: `BrowserWindow.getIcon()` does not exist in Electron 43 (research D7)

**Target Platform**: Windows 10/11 (NSIS installer + portable zip + Scoop), macOS 13+ (DMG/zip), Linux XDG desktops (AppImage)

**Performance Goals**: N/A — static assets; no keystroke-path code

**Constraints**: No artwork redesign or regeneration (assets fixed at commit 5c2d35a); additive electron-builder changes only; no changes to installer.nsh, Scoop/Brew manifests, or update scripts

**Scale/Scope**: 1 YAML edit, 1 main-process wiring edit, 1 new unit-test file, 1 extended test file, 1 e2e spec, planning artifacts + provenance doc

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-checked after Phase 1 design: unchanged — the design adds static assets and packaging metadata only; no renderer, IPC, path-validation, or save-surface changes.*

| Principle | Impact |
|-----------|--------|
| I. Process Isolation Is Absolute | None — no preload/IPC/renderer changes; the window icon is set from the main process at construction |
| II. Every Path Is Untrusted | None — no workspace paths touched; the icon path is derived from `__dirname` inside the app install, never from user input |
| III. Never Lose The User's Words | None — no save/discard behaviour affected |
| IV. Calm, Predictable Editing | None — icons load before first paint as part of window construction; no dialogs or focus changes |
| V. Test What Can Corrupt Or Escape | Honoured in proportion to risk — icon formats fail silently when wrong (a bad dimension byte or truncated ICNS chunk ships invisibly), so the committed binaries get structural unit tests |

All gates pass. FR-005's deferral is not a constitution violation but is tracked below because it deviates from the spec as written.

## Complexity Tracking

> **FR-005 deferred by explicit maintainer authorization (2026-08-23).** The spec requires the artwork be produced with AI image generation ("Nano Banana" or Grok) with a human selecting among candidates before commit. That route was **not executed**: the maintainer authorized deferral on 2026-08-23, and the artwork was authored directly by the ox-alpha model as a minimal geometric mark satisfying FR-006 (recognisable at 16×16, legible on light and dark backgrounds) and FR-008 (no third-party imagery). The simpler alternative rejected was blocking the whole phase on access to an image-generation service whose output would still require human curation; the deliverable contract (FR-001/002/003/004/006/007/008) is fully implemented against the committed artwork. If the generation pass runs later, its session record replaces the deferred-route section of `docs/icon-provenance.md` without code changes.
